KEY DESIGN DECISIONS
================================================================================

1. MODULAR ARCHITECTURE
   - 10 files, single responsibility each
   - Clean interfaces between modules
   - Easy to test independently

2. STREAMING OVER BATCH
   - Display responses as they arrive
   - Better UX (no waiting)
   - Lower latency perception

3. PER-DIRECTORY SESSIONS
   - Different projects = different contexts
   - One history file per project
   - Simpler persistence

4. BACKGROUND TASKS
   - Long operations don't block REPL
   - Users continue working
   - Matches shell expectations

5. TEST-DRIVEN IMPLEMENTATION
   - 54 tests define all requirements
   - Tests run before implementation
   - Ensures correctness

RISK MITIGATION
================================================================================

POTENTIAL RISKS & MITIGATION:

1. RISK: REPL loop hangs
   MITIGATION: Tests catch hangs, timeouts on I/O

2. RISK: History file corruption
   MITIGATION: Atomic writes, recovery from backup

3. RISK: API streaming breaks
   MITIGATION: Streaming interface tested, fallback to batch

4. RISK: Memory grows unbounded
   MITIGATION: History size capped (10k messages max)

5. RISK: Bash command escapes
   MITIGATION: Tool framework handles execution safely

6. RISK: Lost session state
   MITIGATION: Persist after each command

All risks identified and mitigated in design.
